# 官方 API 收尾策略、数据目录整理与 GitHub 同步

更新：2026-10-30。

## 官方标注平均需要多久

在当前配置 `deepseek-flash / thinking=true / reasoning_effort=auto / compact-v2` 下，正式任务共有710次成功标注、25次失败或中断记录。失败不混入成功耗时均值，本地复用旧响应也不作为一次远端标注计时。

| 指标 | 耗时 |
| --- | --- |
| 成功调用平均 | 119.15秒 |
| 中位数 | 108.25秒 |
| P95 | 约237秒 |
| 最慢成功记录 | 394.25秒 |

这些是当前本机正式任务的统计，不是所有模型的通用速度。程序每30秒刷新一次同模型、同思考设置、同协议的历史统计，组内记录不混入官方估算。

## 何时停止加新分子

“仅谷价运行”按北京时间和下一次实际峰价边界计算，不是每天固定倒计时。普通周一至周五09:00–12:00、14:00–18:00为峰价；周末、中国法定节假日按整天谷价处理。[官方价格说明](https://api-docs.deepseek.com/quick_start/pricing/)

预留秒数采用：

```
max(最近500次成功调用的最慢耗时,
    最近500次P99×1.25,
    当前配置等待上限,
    最近50次总超时耗时,
    300秒)
+ 60秒余量
```

当前等待上限600秒，因此当前预留660秒，即11分钟：

- 普通工作日约08:49停止派发，完成在途请求，09:00进入峰价等待。
- 约13:49停止派发，完成在途请求，14:00进入峰价等待。
- 12:00、18:00进入谷价后自动继续。
- 周五18:00后，下一次峰价通常是周一09:00；遇节假日顺延，不在每天23:59无故收尾。

每次提交前重新检查，工作线程真正调用API前再检查一次。停止的是未发出的网络请求，已返回结果的本地解析、入库仍会继续，已发出的请求不因跨入峰价被取消；未请求的pending记录等下一次谷价。失败或结果未知项仍不自动重试。

历史统计可能受到新模型、服务负载和复杂分子的影响；此规则降低跨时段风险，不能保证所有账单都为谷价。当前官方非流式实现不是严格总耗时上限，因此也不把600秒解释成绝对完成保证。不使用平均119秒作为唯一收尾预算。

## 已取消的功能

OpenList/WebDAV网盘上传、对应后台定时器、网页入口和配置接口已撤出。旧实现及说明存入 `trashbin/openlist_removed_20261030/`，不随当前程序发布。GitHub代码同步独立运行，不再依赖网盘或数据库备份任务。

夸克客户端自动备份由用户自行配置。正在写入的SQLite不能按普通文件直接复制并保证一致性：备份时应停止服务后复制三个数据库，或对SQLite一致性快照目录启用夸克备份。只暂停AI不一定能阻止人工继续写入；不要把同步中的文件作为唯一可恢复版本。程序没有替用户配置或验证夸克客户端。

## GitHub 程序同步

仓库：<https://github.com/song-zi-rui/AtomNMR>，分支：`atomnmr-backup`。

手动上传：

```powershell
python tools/sync_annotation_github.py
```

脚本按文件清单上传程序、必要模块、字典、部署模板和文档；不上传data、outputs、trashbin、数据库、日志、真实.env、密钥、虚拟环境或权重。默认不强制推送，上传后核对远端提交SHA。本地发布副本位于 `.code_publish/AtomNMR/`。

本机每日22:00的代码同步使用Windows任务 `AtomNMR-CodeSync-Daily`，入口 `deploy/server/sync-code.ps1`。需要电脑开机、用户已登录且能联网；错过时间后在条件满足时补执行，不唤醒关机的电脑，不索取或保存账户密码。结果日志在 `.code_publish/last-sync.log`。

后台任务每次读取当前Windows用户的系统代理，兼容FlClash变更端口；不依赖Codex终端临时环境，不写死代理端口。代理软件关闭或网络不可用时任务可能失败，错误保留在上述日志和同目录stdout/stderr日志中。

Ubuntu无sudo部署后，可将 `deploy/server/atomnmr-code-sync.{service,timer}` 安装到 `~/.config/systemd/user/`，设置自己的GitHub SSH授权后执行：

```bash
systemctl --user daemon-reload
systemctl --user enable --now atomnmr-code-sync.timer
```

这是独立代码定时器，不承担数据库备份，也不会启动或暂停AI标注。服务器端此处只提供模板，没有远程安装。
