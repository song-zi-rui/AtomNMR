# 标注系统界面与数据库目录调整

日期：2026-10-31。

## 界面

- 主界面顶部删除“SQLite 本地保存”和重复的每日工作量栏；保存中、保存成功或失败等实际状态仍显示。
- 数据统计页首先显示数据库总览，包括总量、谱类型、归属覆盖和双谱进度。
- 下方 AI 标注与人工标注并列、使用相同标题层级和卡片规格：AI 为蓝色，人工为绿色。窄屏自动上下排列。
- 两栏共用日期选择，分别显示每日指标与近 14 天记录。AI 一栏还显示当前标签和模型入库汇总；人工一栏显示当前保留的人工归属。
- 原库标签、AI 入库和人工修改仍按原有口径分别统计，没有改写历史计数，也没有将 AI 操作计入人工工作量。

## 数据文件

新的运行库目录：

```text
data/assignment_database_v1/
├─ databases/
│  ├─ assignments.sqlite
│  ├─ ai_annotations.sqlite
│  └─ ai_benchmarks.sqlite
├─ exports/
├─ backups/
├─ service_logs/
└─ migration_job.json 等报告与状态文件
```

夸克网盘选择 `databases` 文件夹即可圈定三份运行数据库。SQLite 运行期间可能在同目录自动生成 `-wal`、`-shm` 文件，它们是当前事务的辅助文件，不应手工删除。需要确定的一致性备份时，先暂停自动标注、保存页面修改并停止服务，再做整个文件夹备份；不要只拷贝仍在写入的单个主文件。

导出、日志、历史备份、迁移报告及服务器锁文件均留在外层，避免后续又进入三库目录。

## 程序依赖

- `annotation_tool_v3/paths.py` 统一定义主库、两份 AI 库及外层产物位置。
- 桌面启动、AI 标注、模型对比、导出、质量处理、迁移报告、维护和审计工具已更新。
- 本机旧主库路径在旧文件已迁走后会转到新库，避免旧命令误建空库；新旧主文件同时存在时不会自行覆盖或选择。
- Ubuntu 用户启动脚本优先使用 `data/databases/`，同时兼容尚未迁移的旧服务器布局。服务器模板和部署说明已同步更新；本次没有连接或改动远端服务器。

## 迁移与验证

迁移工具为 `tools/relocate_annotation_databases.py`，仅离线使用：停止服务，合并 WAL，检查数据库，进行同盘重命名，再核对 SHA256 和关键表记录数。目标已存在时拒绝覆盖；文件校验失败会回退已移动文件。

本机迁移记录位于 `outputs/annotation_layout_20261031/database_relocation.json`。界面检查截图和检查结果在同目录。布局测试覆盖桌面与 390px 手机宽度，检查了两栏层级、宽度、颜色、日期切换及整页横向溢出；不会提交生产标注。
