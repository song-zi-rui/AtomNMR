## 暂停现在如何工作

点击暂停后立即停止派发新的分子。已发请求继续接收，完整响应先归档、校验，再按各任务规则保存；所有在途请求收尾后进入“已暂停”。普通自动标注、旧 AI 批次和模型测试台都采用此规则。

暂停不会主动关闭已发请求的 HTTP/流式连接。暂停等待中请保持标注服务运行；关闭浏览器不影响后台接收。正常超时、供应商错误或网络故障仍可能造成失败，不能承诺这些情况下也有完整结果。未确认结果不会自动重发以免重复计费。

强制取消底层连接仍用于服务关闭等场景，不再作为任务页面“暂停”的实现。

## “流式响应过大”是什么

流式是一次 API 请求的响应分成许多 SSE 数据事件逐步返回，最后拼成一份完整答案；不是每个数据块重新调用一次模型。系统只记录思考字符数，不保存思考原文；最终归属答案需要完整返回并通过结构检查才能使用。

旧代码在累计收到超过 8 MiB，或者单行超过 1 MiB 时都报同一个错误。累计限制包含每个事件的 JSON 包装、重复字段和思考输出，因此长思考或碎片化输出可能在最终归属答案很短时，也触发 8 MiB 限制。旧失败诊断没有分别记录命中的限制，所以不能还原每一条具体是哪一种。本机此前有 14 条该类失败记录。

本次将累计传输预算与答案长度分开：总传输预算随请求 token 上限放宽（当前 65,536 token 对应 128 MiB），保留单事件 1 MiB 和最终答案 8,388,608 字符的独立保护；思考原文不累计在内存中。超时和异常重复输出保护继续保留。

新错误会记录 wire_bytes、具体限制类型、累计答案/思考字符数与运行阶段。这样可以分清正常的大量小数据包、单个异常事件、过长答案、模型重复、超时或网络中断。

过去被截断且没有完整归档的响应不能凭空恢复。本次没有自动重发那 14 条结果不确定的旧请求。
