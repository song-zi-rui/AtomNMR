# AtomNMR 在 Ubuntu 无 sudo 服务器上持续标注

服务器保存 SQLite、运行标注网页和队列，组内 API 负责推理。服务可以在本机浏览器和 SSH 都关闭时继续运行。网页监听服务器的 `127.0.0.1`，从自己的电脑通过 SSH 隧道访问。

本指南沿用 2026-10-30 的无 sudo 部署目录，使用 2026-11-12 的代码包。已有服务器数据库的情况请直接看「更新旧部署」。

## 1. 准备和上传

| 文件 | 用途 |
|---|---|
| `deploy/atomnmr-server-code-20261112.zip` | v3 标注系统、组内公开 CA、启动脚本、Python 依赖和本指南 |
| `assignments.sqlite` | 分子、谱峰、已有原子归属和 AI 实际入库结果 |
| `ai_annotations.sqlite` | 正式自动标注任务、续跑进度、响应和失败历史 |
| `ai_benchmarks.sqlite` | 模型测试台历史 |
| `SHA256SUMS` | 核对三个上传快照 |

三个库当前合计约 13 GB，文件在 `data/assignment_database_v1/databases/`。原始 SDF、NMRexp、FID、模型权重、旧版本界面和训练环境无需传输。真实 API key 在服务器上录入。

**先在本机暂停自动标注并等到「已暂停」，停掉模型测试任务，保存人工修改，再停止所有会写这三份库的程序。** 从项目根目录的 PowerShell 执行下列命令，替换 SSH 用户名和服务器地址。`$snapshot` 用有至少约 13 GB 空余空间的磁盘，目录必须是新的。

```powershell
$remote = 'yourname@your-server'
$snapshot = Join-Path $env:USERPROFILE 'atomnmr-transfer\snapshot-20261112'
python .\deploy\server\snapshot_databases.py --source .\data\assignment_database_v1\databases --output "$snapshot"
if ($LASTEXITCODE -ne 0) { throw 'Snapshot failed' }
ssh $remote 'umask 077; mkdir -p ~/atomnmr_upload/db; chmod 700 ~/atomnmr_upload ~/atomnmr_upload/db'
scp .\deploy\atomnmr-server-code-20261112.zip "${remote}:~/atomnmr_upload/"
scp "$snapshot\assignments.sqlite" "$snapshot\ai_annotations.sqlite" "$snapshot\ai_benchmarks.sqlite" "$snapshot\SHA256SUMS" "${remote}:~/atomnmr_upload/db/"
```

脚本用 SQLite 自带备份接口读取已提交的 WAL 数据并检查快照。只上传列出的三个 SQLite 文件与校验清单。迁移后以服务器为写入主库，本机快照可用于留档。

## 2. 服务器首次安装

SSH 登录后在 Ubuntu 的 Bash 中执行。给上传暂存、运行库和未来备份预留空间，数据库放到服务器本地磁盘。建议 Python 3.11 或 3.12。

```bash
set -e
umask 077
root="$HOME/atomnmr"
cd "$HOME/atomnmr_upload/db"
sha256sum -c SHA256SUMS
mkdir -p "$root/data/databases" "$root/secrets" "$root/logs"
for path in app data/assignments.sqlite data/databases/{assignments,ai_annotations,ai_benchmarks}.sqlite; do
  if [[ -e "$root/$path" ]]; then echo "Existing installation: $root/$path" >&2; exit 1; fi
done
mkdir "$root/app"
python3 -m zipfile -e "$HOME/atomnmr_upload/atomnmr-server-code-20261112.zip" "$root/app"
cp -n assignments.sqlite ai_annotations.sqlite ai_benchmarks.sqlite "$root/data/databases/"
chmod 600 "$root/data/databases/"*.sqlite
python3 -m venv "$root/venv"
"$root/venv/bin/python" -m pip install -r "$root/app/deploy/server/requirements.txt"
```

若系统 Python 缺少 `venv` 或 `ensurepip`，可用组里的 Conda。在一个空目录执行 `conda create -p "$HOME/atomnmr/venv" python=3.12 pip -y`，再执行上面的依赖安装。若当前 `venv` 目录已有失败的半成品，先把它改名留档。

配置密钥和 API。下面从示例生成 `$HOME` 下的绝对 CA 路径。

```bash
root="$HOME/atomnmr"
cp -n "$root/app/deploy/server/atomnmr.env.example" "$root/secrets/atomnmr.env"
chmod 600 "$root/secrets/atomnmr.env"
nano "$root/secrets/atomnmr.env"
```

填入 `ATOMNMR_API_KEY='你的组内密钥'`，首次 `ATOMNMR_RESUME_JOB_ID` 留空。端口默认 8767。同一服务器上如已被占用，可修改 `ATOMNMR_PORT`，后续健康检查和 SSH 隧道的服务器端端口也要对应修改。

```bash
umask 077
python3 - <<'PY'
import json
from pathlib import Path
root = Path.home() / 'atomnmr'
cfg = json.loads((root / 'app/deploy/server/api.example.json').read_text())
cfg['api']['ca_file'] = str(root / 'app/annotation_tool_v3/certificates/ai-cluster-ca.crt')
with (root / 'api.json').open('x') as out:
    json.dump(cfg, out, indent=2)
PY
bash ~/atomnmr/app/deploy/server/start-user.sh --check-api
```

API 模板沿用已记录的 `https://10.8.130.88/v1` 和模型 ID `deepseek-v4.1-flash`，默认固定并行 1、流式、V3、8,192 输出 token、600 秒超时、思考关闭。`deepseek-DigitalChemistry` 是之前的密钥显示名。正式设置写在 `~/atomnmr/api.json`，服务每次启动会重新加载。若在网页改过任务的模型或思考开关，应把服务器配置同步成同样的值，才能自动恢复该任务。`--check-api` 只查询 `/models`。`selected_model_found: true` 说明当前地址和密钥能查询到模型，实际能否生成归属要看正式队列的第一批响应。

## 3. 后台运行

优先使用用户级 systemd。`Linger=yes` 才能按此方案在注销后维持用户管理器，并在服务器开机时启动。是否能启用取决于服务器授权策略。 [systemd loginctl 文档](https://freedesktop.org/software/systemd/man/latest/loginctl.html)

```bash
loginctl show-user "$(id -un)" -p Linger
```

如果显示 `Linger=no`，单独执行 `loginctl enable-linger "$(id -un)"`，再查一次。确认 `Linger=yes` 后安装服务。

```bash
mkdir -p ~/.config/systemd/user
cp ~/atomnmr/app/deploy/server/atomnmr-user.service ~/.config/systemd/user/atomnmr.service
systemctl --user daemon-reload
systemctl --user enable --now atomnmr.service
curl --fail http://127.0.0.1:8767/api/health
journalctl --user -u atomnmr.service -n 50 --no-pager
```

用户级 systemd 不可用时，可以选择 `nohup` 并实测断开 SSH 后进程是否存活。该方式需要手动处理进程退出或服务器重启。两种启动方式只选一种。

```bash
nohup bash ~/atomnmr/app/deploy/server/start-user.sh >> ~/atomnmr/logs/server.log 2>&1 </dev/null &
echo $! > ~/atomnmr/server.pid
```

## 4. 启动队列，查看新标注

在本机 PowerShell 开一个 SSH 隧道。这个窗口只负责连接网页。

```powershell
ssh -N -T -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 127.0.0.1:18767:127.0.0.1:8767 yourname@your-server
```

1. 打开 [服务器上的自动标注页](http://127.0.0.1:18767/auto.html?results=applied)。检查组内模型和并行数，处理范围选 **仅处理双谱无归属分子**，给任务起个便于辨认的名字，点 **开始持续标注**。服务器模式默认这个范围，继续按已有归属校验规则写库。
2. 先看前几条。**最新新增归属（30 条）** 只显示确实写入至少一个新归属峰的记录，按入库时间排序。点分子式直接打开该分子，点行内其他位置看 AI 结果和逐峰依据。页面在任务运行时自动刷新。看失败原因时切到 **未解决失败分子**。
3. 在 **运行详情与用量** 复制完整任务 ID。想固定书签可用 `http://127.0.0.1:18767/auto.html?results=applied&job=完整任务ID`。关闭本机浏览器和隧道后，服务和任务继续运行。
4. 让同一个任务在重启后自动继续。在网页点 **暂停标注**，等在途请求收尾。把完整 ID 写入 `~/atomnmr/secrets/atomnmr.env` 的 `ATOMNMR_RESUME_JOB_ID`，运行 `systemctl --user restart atomnmr.service`。这次是手动暂停，所以重启后在网页点 **继续后续分子** 一次。之后服务退出或服务器重启，系统会恢复指定的中断任务。手动暂停、错误待处理和已完成的任务保持各自状态。

组内 API 模板给指定队列配置了 90 秒冷却。单次超时、连接中断或部分网关错误会记入失败，冷却后领取下一个分子。同一运行中连续三次失败，或收到限流、鉴权、证书等错误，队列会停在 **需要处理错误**。已发送但结果未知的分子由你决定是否重试。恢复时优先点 **继续后续分子**，会沿用原任务进度。另开新任务可能重新选到仍符合范围的旧失败分子。

## 5. 更新旧部署

服务器已经有运行库时，**只上传新代码包**。先通过网页暂停并等在途请求收尾。把旧库保留在服务器现有位置，先备份，再替换 `app` 目录。

```bash
set -e
root="$HOME/atomnmr"
cd "$root"
systemctl --user stop atomnmr.service
test ! -e app-20261112 && test ! -e app-before-20261112
mkdir app-20261112
python3 -m zipfile -e "$HOME/atomnmr_upload/atomnmr-server-code-20261112.zip" app-20261112
"$root/venv/bin/python" -m pip install -r app-20261112/deploy/server/requirements.txt
mv app app-before-20261112
mv app-20261112 app
```

如需启用冷却，手动在现有 `api.json` 的根对象增加 `"server": {"transient_cooldown_s": 90}`。继续沿用原密钥文件和模型配置。若旧部署用 Git 自动同步代码，先确认同步源已包含这次更新，避免下一轮替换新目录。运行 `bash ~/atomnmr/app/deploy/server/start-user.sh --check-api`，然后 `systemctl --user start atomnmr.service`，从网页继续原任务。使用 `nohup` 的部署在替换前先核对并停止原进程，再按原方式启动。

备份可复用 `snapshot_databases.py`，在服务停写后把三个库和校验清单存到独立磁盘或备份位置。恢复时以同一份快照为单位。主库和任务历史分别存放，保留同批快照能让归属与续跑状态对应。
