# 夸克备份、GitHub 程序备份和仅谷价标注

更新：2026-10-30。本次已准备程序功能，网盘仍需本人登录授权。不要把 Cookie、密码、API Key 发到聊天或 GitHub。

## 日常怎么用

打开标注系统顶部的“备份”，或访问 `http://127.0.0.1:8767/backup.html`。

1. 第一次配置 OpenList 的 WebDAV 地址、专用用户名和密码，点击“保存设置”，再点“检查连接”。
2. 点击“立即备份并上传”，观察记录，直到显示“云端完成”。建议第一次完成后，立即做一次恢复演练。
3. 勾选自动备份，默认每 24 小时一次，保存设置。关闭网页不影响备份，但标注服务和 OpenList 必须持续运行。
4. “GitHub 程序备份”内已预填 `https://github.com/song-zi-rui/AtomNMR.git`。可单独点“立即上传程序代码”，也可勾选每次数据库上传成功后同步代码。

当前不自动删除云端历史版本。至少保留最近 7 个每日版本和每周、每月版本；清理时先确认有更新且已验证的版本。

## 备份包含什么

数据库使用 SQLite 在线备份接口，不直接复制正在写入的主文件，因此已提交到 WAL 的标注也会进入快照。每个文件单独保持事务一致；三个数据库依次备份，不承诺同一瞬间的跨库原子快照。主数据库是归属成果的恢复依据，AI 任务库时间可能略晚。

| 文件 | 内容 |
| --- | --- |
| assignments.sqlite | 分子、实验谱、现有归属、修订及来源 |
| ai_annotations.sqlite | 正式 AI 任务、调用结果及原有加密密钥信息 |
| ai_benchmarks.sqlite | 测试台、固定测试集合及评分 |
| manifest.json | 文件与分块大小、SHA256、开始结束时间、恢复说明 |

数据库分成每块最多 1 GiB 的文件直接上传，不额外在本机生成整套分块副本。云端目录形如 `snapshot-20261030T120000Z-xxxxxxxx/`。`manifest.json` 最后上传，是完成标志。上传后逐块检查大小、读回清单；**尚未对云端全部块重新下载计算 SHA256**，因此恢复时必须再做完整校验。

默认上传验证完成后，清理本次生成的本地临时 SQLite 文件，保留清单和历史记录。这不会删除在线数据库，也不会删除云端版本。上传失败的完整快照会保留，点击“重新上传此快照”不会重新读取当前数据。未完成的损坏/失败快照会清理其临时数据库，以免占满工作盘。

这三个数据库通常需要十几 GB 空间。创建快照前会要求至少总大小的 1.15 倍加 512 MB 可用空间；OpenList 中转还可能使用额外缓存空间，请另行预留。完整快照、完整校验和上传都会产生磁盘、网络负载，适合先每天一次，确认耗时再缩短间隔。

备份控制文件位于数据库同级 `backup_control/`。不要把此文件夹整体上传 GitHub：其中包含 WebDAV 登录信息与代码备份仓库。Windows 的 WebDAV 密码使用当前用户 DPAPI；Ubuntu 使用权限 600 的私密配置文件，目录权限 700。Windows 原有 API Key 不能依靠备份迁移后在 Ubuntu 解密，服务器仍应通过私密环境文件设置 API Key。

## 为什么接 OpenList

夸克不是原生 WebDAV 服务。OpenList 在你自己的电脑/服务器上连接夸克，本系统通过它上传文件。夸克驱动依赖非官方接口，可能受登录失效或接口变动影响，不能保证永久可用；失败必须看到记录并处理。后续换百度，只需换 OpenList 挂载及本系统地址，数据库备份格式不变。

参考：[OpenList 夸克驱动](https://doc.oplist.org/guide/drivers/quark)、[WebDAV 设置](https://pages.doc.oplist.org/guide/advanced/webdav)。普通夸克驱动才适合尝试上传；**夸克TV只支持访问与下载，不能用作备份上传端**。

## Ubuntu 无 sudo 的 OpenList 配置

建议与标注服务安装在同一服务器，免去 Windows 电脑必须一直开机的要求。

1. 按 [OpenList 官方手动安装说明](https://doc.oplist.org/guide/installation/manual)，从 [官方 Releases](https://github.com/OpenListTeam/OpenList/releases) 下载适合 `uname -m` 架构的 Linux 二进制包。使用二进制运行，无需 sudo 或 Docker。解压到 `~/atomnmr/openlist/`，不要使用需要 sudo 的 APT 安装步骤。
2. 在该目录执行 `chmod +x openlist`，再运行 `./openlist server`。使用 `./openlist server --help` 核对所用版本参数。第一次生成配置后，将 HTTP 监听地址改为 `127.0.0.1`，默认端口通常是 5244，重启验证后再安装常驻服务。不要把后台管理面板公开到外网。
3. 本地 SSH 增加端口转发：

   ```bash
   ssh -L 15244:127.0.0.1:5244 -L 18767:127.0.0.1:8767 用户名@服务器
   ```

   浏览器通过 `http://127.0.0.1:15244` 管理 OpenList，标注系统在 `http://127.0.0.1:18767/backup.html`。

4. 在 OpenList 的存储设置挂载普通“夸克网盘”，按驱动文档在本人浏览器获取登录 Cookie，**只填进自己的 OpenList 后台**。挂载为 `/夸克`，先在网盘建立 `AtomNMR` 文件夹。
5. 建立只用于备份的 OpenList 用户，限定可访问该文件夹；打开 WebDAV 读取、WebDAV 管理，以及创建目录/上传/删除测试文件权限。不要用匿名账号写入。
6. 本系统的备份地址填写服务器自己能访问的地址，例如 `http://127.0.0.1:5244/dav/夸克/AtomNMR`，用户名密码填写上述 OpenList 备份用户。这里的 5244 是服务器端口，**不是本地 SSH 转发端口 15244**。以“检查连接”成功为准。
7. OpenList 也需常驻运行。可参照 `deploy/server/openlist-user.service` 安装到 `~/.config/systemd/user/`，再执行 `systemctl --user daemon-reload`、`systemctl --user enable --now openlist`。和标注服务相同，开机/退出 SSH 后继续运行依赖用户 systemd 与 Linger 设置，详情见 Ubuntu 无 sudo 部署文档。

OpenList 可能缓存上传内容，首次备份时应检查其缓存目录磁盘占用；不要把数据库放到 OpenList 挂载目录直接运行。

## GitHub 代码怎么同步

使用部署打包器同一份程序文件清单：标注系统、必要数据处理模块、字典、工具、部署模板和说明。排除数据库、权重、运行环境、日志、真实 `.env` 和密钥文件。提交前还检查常见 `sk-...` 密钥。上传的是可阅读的程序文件，不只是压缩包。

代码使用 `atomnmr-backup` 分支，独立本地仓库位于 `backup_control/github-code/`，不会改动工作目录或覆盖 GitHub 主分支；不强制推送。建议仓库保持私有。服务器需要安装 Git，并配置 SSH 或 HTTPS 凭据；本系统不会索取或保存 GitHub Token，也不会后台弹出登录框。

Ubuntu 建议使用 GitHub SSH 密钥，配置在服务器自己的 `~/.ssh/`，把公钥加入 GitHub 后，在 SSH 终端手动验证主机身份和连接。然后把页面地址改为 `git@github.com:song-zi-rui/AtomNMR.git`。不要关闭 SSH 主机身份检查。代码备份会使用 `AtomNMR Backup <atomnmr-backup@localhost>` 提交身份，不依赖系统全局 Git 用户配置。

更换仓库时，如果已有代码备份仓库绑定其他地址，系统拒绝自动切换并推送；应另建备份目录或在确认后手动迁移，避免推错位置。

## 怎么恢复

1. 从夸克下载某个已完成版本的整个目录，包含所有 `.partNNNN` 文件和 `manifest.json`。
2. 使用新的空目标路径运行（在程序目录）：

   ```bash
   python -m annotation_tool_v3.backup_restore --source /下载的快照目录 --output /新的恢复目录
   ```

   程序会顺序合并分块，检查每块与完整文件的 SHA256、大小及 SQLite `quick_check`。目标目录已存在会拒绝运行。只有生成 `RESTORE_OK.txt` 才可继续；失败留下的部分文件不能用来替换数据库。

3. 暂停标注并停止服务，保留当前数据库的现场副本，再把恢复出的三个 SQLite 文件放进新的数据库目录。不要在运行中的旧目录混放旧 WAL/SHM 与恢复文件；优先让服务指向新的恢复目录。
4. 启动后核对分子数、近期人工归属和近期 AI 结果。API Key、OpenList 登录信息、Linux 私密环境文件要另行保管与恢复。

## 官方 DeepSeek：峰价等待，谷价并行

在自动标注页选择官方端点，再选择“仅谷价运行”，并行数量可设为 1–64。希望使用本程序上限时填 64；组内端点继续使用固定并行，不能套用官方价格规则。

- 北京时间，普通周一至周五：09:00–12:00、14:00–18:00 为峰价。
- 其他时段，以及整个周末和中国法定节假日，为谷价。
- 峰价不领取新分子；任务保持等待，谷价自动继续。
- 切换时已发出的请求继续完成，不取消已付费请求、不丢结果。此功能控制发起时间，不承诺跨时段请求的最终账单必然全按谷价。
- 人工暂停及接口异常暂停不会因为进入谷价而自动恢复；保留现有的限流/结果未知保护，不自动重试收费请求。
- 2026 年节假日日历已配置；进入新年份需更新日历，否则工作日按普通工作日保守处理。

截至 2026-10-30，[官方并发文档](https://api-docs.deepseek.com/quick_start/rate_limit/)：`deepseek-flash` 每账号 2500 个并发，`deepseek-v4-pro` 每账号 500 个。不同 Key 共用账号限制。**64 是本程序上限，不是官方账号上限，也不是已经实测过的稳定值**。建议先 16，再 32，最后 64，检查接口错误和本地写入等待；不直接启动 2500 个本地工作线程。

[官方价格时段](https://api-docs.deepseek.com/quick_start/pricing/)规定谷价为峰价一半。当前系统另保留旧的“谷价加速”策略供原任务兼容，不会把组内固定并行配置偷偷换成官方调度。
